# Информационное табло

## 1. Назначение

Информационное табло предназначено для отображения оперативной информации по текущему состоянию трека в течение дня.

Табло должно показывать ключевые показатели в режиме, близком к реальному времени.

Информация на табло используется для быстрого контроля ситуации на треке без необходимости перехода в детальные разделы системы.

## 2. Отображаемые показатели

На информационном табло должны отображаться следующие показатели:

| Показатель | Описание |
| --- | --- |
| Нарушения за день | Общее количество нарушений, зафиксированных системой с начала текущего дня |
| Ученики на треке | Текущее количество учеников, находящихся на треке |
| Инструкторы на треке | Текущее количество инструкторов, находящихся на треке |

## 3. Логика подсчёта нарушений

Система должна автоматически увеличивать счётчик нарушений при появлении нового события в системе «Видеофор». Подсчёт выполняется за текущий календарный день. При появлении нового нарушения в системе значение на табло должно обновляться автоматически.

Пример:

- в 10:00 зафиксировано 5 нарушений;
- в 10:15 появилось новое нарушение;
- на табло автоматически отображается 6 нарушений.

В конце дня счётчик должен сбрасываться и начинать новый подсчёт со следующего дня.

## 4. Логика подсчёта транспорта

Система должна автоматически увеличивать счётчик транспортных средств при выезде транспорта из гаража (ТК1). Подсчёт выполняется за текущий календарный день. При появлении нового транспортного средства значение на табло должно обновляться автоматически.

## 5. Количество учеников на треке

На табло должно отображаться текущее количество учеников, находящихся на треке. Показатель должен обновляться автоматически при изменении количества учеников.

## 6. Количество инструкторов на треке

На табло должно отображаться текущее количество инструкторов, находящихся на треке.

## 7. Требования к отображению

На табло должны быть крупно и понятно отображены все основные показатели.

Рекомендуемый формат:

```
Нарушения за день:    12
Транспорт за день:    48
Ученики на треке:     16
Инструкторы на треке:  3
```

Для каждого показателя должно отображаться название показателя, числовое значение, текущая дата.

## 8. Интеграция с системой «Видеофор» и информационным табло

Информационное табло должно получать данные из системы «Видеофор» через внешний сервис интеграции.

В качестве промежуточного компонента используется внешний сервис, реализованный на Python. Сервис принимает данные от системы «Видеофор», обрабатывает их и передаёт актуальные значения на информационное табло по API.

Обмен данными между системой «Видеофор», внешним сервисом и информационным табло выполняется в формате JSON.

### 8.1. Общая схема взаимодействия

Общая логика взаимодействия компонентов:

1. Система «Видеофор» фиксирует событие или изменение показателя.
2. «Видеофор» отправляет данные во внешний сервис интеграции.
3. Внешний сервис на Python принимает JSON-запрос.
4. Сервис обрабатывает полученные данные и обновляет соответствующий показатель:
   - количество нарушений за день;
   - количество транспорта за день;
   - количество учеников на треке;
   - количество инструкторов на треке.
5. Внешний сервис передаёт обновлённые данные на информационное табло по API.
6. После успешной обработки внешний сервис отправляет в систему «Видеофор» ответ в формате JSON о том, что данные получены и переданы для отображения на табло.

### 8.2. Формат обмена данными

Передача данных должна выполняться в формате JSON.

Пример структуры входящего сообщения от системы «Видеофор»:

```json
{
  "event_type": "violation",
  "event_time": "2026-06-09T10:15:00",
  "source": "Videofor",
  "object_type": "transport",
  "checkpoint": "TK1",
  "value": 1
}
```

Состав полей может быть уточнён на этапе согласования API.

Обязательные данные для передачи:

- тип события;
- дата и время события;
- источник события;
- значение или признак изменения показателя;
- при необходимости — точка фиксации, например ТК1.

### 8.3. Ответ внешнего сервиса

После получения и обработки данных внешний сервис должен отправлять ответ в формате JSON.

Пример ответа:

```json
{
  "status": "success",
  "message": "Data received and displayed",
  "received_at": "2026-06-09T10:15:05"
}
```

В случае ошибки сервис должен возвращать ответ с описанием причины ошибки.

Пример ответа при ошибке:

```json
{
  "status": "error",
  "message": "Invalid event type"
}
```

### 8.4. Требования к внешнему сервису

Внешний сервис должен:

- принимать данные от системы «Видеофор» в формате JSON;
- проверять корректность полученных данных;
- определять, к какому показателю относится полученное событие;
- обновлять соответствующий показатель на информационном табло;
- отправлять подтверждение о получении и обработке данных;
- обрабатывать ошибки при некорректном формате данных или недоступности табло.

### 8.5. Требования к API информационного табло

Информационное табло должно иметь API для получения актуальных значений показателей от внешнего сервиса.

Через API должны передаваться следующие данные:

- количество нарушений за текущий день;
- количество транспорта за текущий день;
- текущее количество учеников на треке;
- текущее количество инструкторов на треке;
- дата и время последнего обновления.

При получении новых данных табло должно автоматически обновлять отображаемые значения без ручного обновления страницы.
