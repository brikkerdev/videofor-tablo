# API информационного табло (LED Matrix)

Версия: 1.0
Дата: 2026-06-10
Статус: восстановлено реверс-инжинирингом по штатному веб-интерфейсу шлюза.

## 1. Топология

Табло состоит из двух устройств:

```
наш сервис ──HTTP/JSON──> ESP32-шлюз (192.168.0.64) ──внутр. протокол──> LED-матрица (192.168.0.47)
                              REST + SSE                  remotefunction
```

| Узел | Адрес | Роль |
| --- | --- | --- |
| LED-матрица | `192.168.0.47:80` | Физическая панель 256×96. Внутренний бинарно-текстовый протокол `remotefunction`, пароль `guest`. Хрупкий, недокументированный. **Напрямую не использовать.** |
| ESP32-шлюз | `192.168.0.64:80` | Мост. Держит подключение к матрице, отдаёт чистый REST API + SSE, CORS `*`. **Точка интеграции.** |

Сервер шлюза: `Server: ESP32`. Все ответы JSON, заголовки CORS открыты (`Access-Control-Allow-Origin: *`).

Интеграция работает только со шлюзом `192.168.0.64`. Раздел 5 описывает протокол самой матрицы для справки и аварийных случаев.

## 2. Параметры панели

Запрашиваются через `GET /connect.json` (раздел 3.1). На текущем устройстве:

| Параметр | Значение |
| --- | --- |
| Ширина | 256 px |
| Высота | 96 px |
| Яркость | 0..255 (текущая 255) |
| Питание `onoff` | 1 — включено |
| IP матрицы | 192.168.0.47 |

Доступные шрифты (`fontlist`):

```
SimHei, Times New Roman, Verdana, Tahoma, NSimSun,
Arial, SimSun, KaiTi, DigifaceWide, Georgia, Segoe UI
```

## 3. REST API шлюза

База: `http://192.168.0.64`. Тело и ответы — JSON. Для POST использовать заголовок `Content-Type: application/json`.

### 3.1. GET /connect.json

Состояние подключения шлюза к матрице и параметры панели.

Ответ 200:

```json
{
  "connected": true,
  "ip": "192.168.0.47",
  "width": 256,
  "height": 96,
  "brightness": 255,
  "onoff": 1,
  "fontlist": ["SimHei", "Times New Roman", "Verdana", "Tahoma", "NSimSun",
               "Arial", "SimSun", "KaiTi", "DigifaceWide", "Georgia", "Segoe UI"]
}
```

При отсутствии подключения `connected: false`, остальные поля могут отсутствовать.

> Проверено на устройстве: уже подключённый шлюз отдаёт `connected:true`, `ip` (адрес матрицы) и размеры панели сразу, без открытого SSE и без `POST /connect.json`. Интеграция использует этот ответ как источник правды о связи (`refresh_status` в `app/tablo.py`). `POST /connect.json` (раздел 3.2) нужен только когда шлюз отвечает `connected:false` — поднять связь с нуля.

### 3.2. POST /connect.json

Подключить шлюз к матрице. Шлюз сохраняет подключение, повторно вызывать не требуется.

Запрос:

```json
{ "bx-ip": "192.168.0.47", "bx-pass": "guest" }
```

Ответ 200: то же тело, что у `GET /connect.json`.

### 3.3. POST /message.json — вывод текста (основной эндпоинт)

Выводит на панель набор текстовых областей. Тело — **JSON-массив** объектов-областей.

Запрос:

```json
[
  {
    "id": "0",
    "msg": "Нарушения за день: 12",
    "x": "0",  "y": "0",
    "w": "256", "h": "32",
    "fontname": "Arial",
    "fontsize": "20",
    "fontcolor": "0xffffffff",
    "stunt": "0"
  }
]
```

Поля области:

| Поле | Тип | Описание | Ограничения |
| --- | --- | --- | --- |
| `id` | string | Идентификатор области | Стабильный. Повторная отправка того же `id` заменяет область на месте |
| `msg` | string | Текст области | Пустая строка `""` — очистить (удалить) область. **Поле обязательно: его отсутствие роняет шлюз** |
| `x` | int px | Левый край | `0..255`, `x + w ≤ 256` |
| `y` | int px | Верхний край | `0..95`, `y + h ≤ 96` |
| `w` | int px | Ширина области | |
| `h` | int px | Высота области | |
| `fontname` | string | Имя шрифта | Одно из `fontlist` (раздел 2) |
| `fontsize` | int | Кегль, px | Интерфейс ограничивает `6..99` |
| `fontcolor` | string | Цвет `0xAARRGGBB` | См. ниже |
| `stunt` | int | Эффект/анимация | `0` — статично, `2` — по умолчанию в интерфейсе. Диапазон `0..100` |

Значения полей можно передавать строками (как штатный интерфейс) или числами — принимаются оба варианта. `fontcolor` принимается строкой `"0xffffffff"` или целым числом.

Цвет — ARGB, формат `0xAARRGGBB`:

| Цвет | Значение |
| --- | --- |
| Белый | `0xffffffff` |
| Красный | `0xffff0000` |
| Зелёный | `0xff00ff00` |
| Синий | `0xff0000ff` |

Ответы:

| Код | Тело | Значение |
| --- | --- | --- |
| 204 | пусто | Успех |
| 400 | `InvalidInput` | Невалидный JSON или значения полей |
| 400 | `Bad request` | Неверный метод (например GET) |
| 400 | `Service Unavailable` | Пустой массив `[]` запрещён |

#### Семантика областей

- Области адресуются по `id` и **сохраняются на панели** между запросами.
- POST задаёт/заменяет перечисленные в массиве области. Области, не вошедшие в массив, остаются на экране.
- Чтобы убрать область — отправить её с `"msg": ""`. Пустой массив для очистки не годится (ответ `Service Unavailable`).
- Поэтому при уменьшении числа строк нужно явно гасить освободившиеся `id` отправкой `msg: ""` (см. клиент `app/tablo.py`).

#### Пример: две строки

```json
[
  {"id":"0","msg":"Нарушения за день: 12","x":"0","y":"0","w":"256","h":"48",
   "fontname":"Arial","fontsize":"24","fontcolor":"0xffff0000","stunt":"0"},
  {"id":"1","msg":"Ученики на треке: 16","x":"0","y":"48","w":"256","h":"48",
   "fontname":"Arial","fontsize":"24","fontcolor":"0xff00ff00","stunt":"0"}
]
```

### 3.4. GET /settings.json

Сетевые настройки шлюза.

```json
{
  "net_dhcp": true,
  "net_ip": "192.168.0.64",
  "net_mask": "255.255.255.0",
  "net_gw": "192.168.0.1",
  "net_dns": "192.168.0.1"
}
```

### 3.5. POST /settings.json

Сохранить сетевые настройки. Тело — те же поля, что в 3.4 (`net_dhcp` булево, остальные — строки IP). Применяется на стороне шлюза.

### 3.6. GET /sse.json — поток событий (Server-Sent Events)

`text/event-stream`. Сообщения с типом `event`, в `data` — JSON. Возможные ключи:

| Ключ | Содержимое |
| --- | --- |
| `fonts` | Массив доступных шрифтов |
| `device` | `{ "width", "height", "brightness", "onoff" }` |
| прочие | `{ "<операция>": true \| false }` — подтверждение/ошибка операции |

Поток нужен веб-интерфейсу для статуса. Для серверной интеграции не обязателен: результат `POST /message.json` определяется HTTP-кодом ответа.

### 3.7. POST /update

Загрузка прошивки шлюза, `multipart/form-data`, поле файла `myFile`. К интеграции отношения не имеет, приведено для полноты.

## 4. Замечания по надёжности шлюза (важно)

Эти ограничения выяснены экспериментально и критичны для стабильной работы.

- **Связь держится только при открытом SSE.** Шлюз подключается к матрице и логинится по потоку `GET /sse.json` (события `verificationcode` → `login` → `device`). Как только поток закрывается, `connected` становится `false` и вывод не отображается. Интеграция обязана постоянно держать один открытый SSE (см. `app/tablo.py`, фоновый `_sse_keeper`).
- **Порядок входа:** открыть SSE → подождать ~2с → `POST /connect.json` → дождаться события `device` в SSE (готовность). Только после этого слать `message.json`.
- **Мало TCP-соединений.** ESP32 не держит много сокетов. Безопасно: один постоянный SSE плюс один короткий запрос за раз (без keep-alive, сериализованно). Частые параллельные соединения valют шлюз: `503` и обрыв SSE.
- **Не больше ~4 областей в одном `POST /message.json`.** Больше — `503`. Так как области накапливаются по `id` между запросами, полный экран шлём пачками по 4 с небольшой паузой.
- **Не слать `message.json` без связи.** При `connected:false` ответ `503`, и это сбивает установление SSE. Сначала дождаться связи.
- **Не частить.** Всплески событий коалесим: не чаще одного обновления в ~2с (`app/pusher.py`).
- Тело `POST /message.json` — валидный JSON-массив. Каждый объект **обязан** содержать ключ `msg`; объект без `msg` (`[{}]`, `[{"id":0}]`) обрывает соединение.
- `Content-Type: application/json`. Идемпотентность по `id`: повторный POST с тем же `id` перерисовывает область.

## 5. Внутренний протокол матрицы (192.168.0.47) — справочно

**Через этот интерфейс штатно не работаем.** Им занимается шлюз. Приведено на случай отказа шлюза и для понимания природы ошибок.

- nginx + Python-бэкенд, `POST /`. Авторизация — пароль `guest` (обрабатывается шлюзом).
- Тело — сырой JSON. С `Content-Type: application/json` фреймворк перехватывает тело и обработчик падает; рабочий путь — отправлять JSON как `text/plain`.
- Конверт запроса: `{ "remotefunction": { "name": "<функция>", ... } }`.
- Конверт ответа: `{ "remotefunction": { "error": { "code": <int>, "mesg": "<текст>" }, "name": "<эхо>" } }`.

Наблюдавшиеся коды ошибок:

| code | mesg | Причина |
| --- | --- | --- |
| 2 | `Request Method PUT Error` | Недопустимый HTTP-метод |
| 3 | `Expecting value: line 1 column 1 (char 0)` | Тело не распарсилось как JSON |
| 255 | `Other error : ...` | Внутреннее исключение Python (например незаданные обязательные поля) |

Полный набор функций матрицы (`name`) не задокументирован и не реверсился: интеграция идёт через шлюз, где контракт стабилен.

## 6. Как это использует наш сервис

- Клиент шлюза: `app/tablo.py` (`POST /message.json`, гашение устаревших областей).
- Сборка областей из показателей и верхней панели: `app/render.py` (`render_areas`).
- Конфигурация вывода (какие показатели и верхняя панель) задаётся через API сервиса и веб-интерфейс, см. `docs/tech-design.md` разделы про `/api/display/*`.
- Базовый адрес шлюза — переменная окружения `TABLO_URL` (например `http://192.168.0.64`).
